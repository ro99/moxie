# Task contract — replace placeholders before work

Status: proposed / active / blocked / accepted / rejected.

## Identity and authority

- Task ID, milestone, owner/reviewer:
- Writable repository root, branch/base commit, initial dirty paths:
- Read-only legacy root and frozen source commit:
- Requirement / finding IDs repaired:
- Required documents and source/test references:
- Owner gates already resolved; remaining gates and stop point:

## Bounded deliverable

- One concrete outcome:
- Sole owning shared component:
- Allowed production and test files/modules:
- Explicit non-goals and forbidden shortcuts:
- Existing consumers and second-consumer/shape proof:
- Temporary paths to delete or bridge expiry:

## Contract before implementation

- Equations and semantic input/output/state effects:
- Shapes, precision, accumulation/rounding, logical/physical layout:
- Partition and hardware capabilities:
- Peak memory and transfer dependencies; source/lease lifetime:
- Cancellation, failure and rollback behavior:
- Independent oracle; predeclared numerical metrics/thresholds:
- Application compatibility and sampler implications:

## Acceptance

- Architecture / host / GPU / distributed / state tests and required hardware:
- Actual-context cases and prefill/decode/quality/memory gates:
- Benchmark manifest, baseline identity, variance/repetition plan if applicable:
- Support-matrix entries to update:
- Deletion and documentation gates:
- Exact condition requiring owner direction or task rejection:

## Result, filled after work

- Changed shared owners and consumers; source commit:
- Commands and result IDs; passed / failed / skipped separately:
- Measured effect and uncertainty:
- Deleted/replaced paths:
- Remaining blockers and next bounded task:

Do not fill acceptance with “model works” or “faster.” Missing oracle, context, memory or ownership evidence is not an accepted task.
